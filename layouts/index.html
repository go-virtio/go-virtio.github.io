GitHub common module

go-virtio implements virtio device-class drivers in pure Go — no cgo, no kernel — routing every transport-level operation through one narrow common.Transport interface, so the same driver code runs under UEFI, bare-metal MMIO, virtio-mmio, or any backplane that satisfies the contract. Eight drivers sit on top of a single shared common waist (PCI cap walker, modern-config registers, split-virtqueue with descriptor chaining). Extracted from the cloud-boot TamaGo + UEFI loader, designed to run anywhere virtio runs.

Every driver consumes common.Transport and nothing else — swap the backplane, keep the driver. The 3D story is split honestly: gpu/soft3d is a dependency-free CPU rasterizer that works on any host; gpu's virgl path hand-encodes the command stream so a host GPU draws (still CGO=0); and venus is Vulkan-over-virtio with a vk.xml→Go generator, a shared-memory ring, and guest-side pixel readback. All eight drivers plus virgl 3D and the full Venus clear-image-with-readback are validated on real devices and renderers — and real-hardware validation has caught 9 encoding bugs that fake-device unit tests missed. Pure Go with no architecture-specific assembly: the same source builds for every Go target (amd64, arm64, riscv64, loongarch64). First consumer: cloud-boot.
